- 2026-10-13 — [backend, shared, web, docs] — **P13.3 go-live import and the user guide (ONB-01).** Four kinds of file — parties, items and brick grades, opening balances, opening stock — each with a template to fill in. **Check** reads the file and says what would happen, writing nothing; **Import** writes it, and only if every row is good. All-or-nothing is the point: a half-imported party list at go-live is worse than none, because nobody can tell which half landed, re-running duplicates it, and the kiln's first week of real entries is made against a master list no one trusts. Problems are reported per row with the **line number from the operator's own spreadsheet** and the field that caused them. The CSV is parsed **in the browser** and only the rows are sent — nothing is uploaded, so there is no file to store or scan, and the whole import needs no object storage. Each kind goes through the code that already owns it rather than inserting rows: a party is created with its ledger (PTY-01 — `PartyService.createWithin` was extracted so the import joins the caller's transaction instead of opening its own), a brick grade is created with the item it sells as (ADR-051), and opening stock goes through `StockService`, so the one-opening-per-pile rule holds. **A gap this exposed:** the chart had a Capital *group* and no ledger under it, so a kiln could enter everything it owns — all debits — and have nothing to credit. The opening set could never balance and the first Balance Sheet would be wrong by the whole of the owner's own money. `OWNERS_CAPITAL` is now seeded and backfilled onto every existing company. That also closes **ACC-04**'s missing screen: opening balances are enterable at last. `docs/16-user-guide.md` is written for the people who will use this daily, in the order of a working day, and ends with the things the system refuses and why — each one a mistake that is expensive to find later. 14 new backend e2e (686 → **700**) and 10 new web tests (146 → **156**), including the CSV reader's awkward cases: a comma inside a quoted field, a doubled quote, Excel's byte-order mark, Windows line endings, and a short row that must not shift its columns along. — ONB-01, ACC-04
- 2026-10-13 — [backend, web] — **GST-02 — the tax charged now has to match where the goods are going.** The CGST/SGST-vs-IGST split has worked since P8 and the two could never appear on one line, but **nothing compared the choice against the place of supply**: an invoice to a Delhi customer could be charged CGST + SGST and only the PDF noticed, printing "Place of Supply … (Inter-state)" beside intra-state tax — the one line that stated it confidently was the line that was wrong. That is not a rounding difference; it is tax paid to the wrong government, which the kiln answers for at filing with interest. Now refused with `GST_PLACE_OF_SUPPLY_MISMATCH` on **sales invoices (lines and charges), credit notes, debit notes and supplier bills** — the party's state code against the company's decides it, and the message says which tax the document should carry rather than only that it is wrong. A party with no state recorded is treated as **intra-state**, because for an unregistered buyer whose address was never taken the place of supply is the supplier's own location; that is the rule, and it also keeps a cash counter sale from being blocked by a blank field. The forms stop inviting the mistake: the invoice dialog shows only the applicable tax fields and says in words which applies and why, and the supplier-bill dialog offers one rate row instead of an in-state set beside an IGST set. 2 new backend e2e (680 → **682**) and 1 new web test (145 → **146**). — GST-02, GST-03
- 2026-10-13 — [backend, web, docs] — **P13.1 e2e core flows + security review.** The pre-go-live pass. Three real holes were open and are now closed. **Login could be guessed at:** `/auth/login` accepted unlimited attempts from one address — now 10 a minute, 30 on `/auth/refresh` (it also takes a secret), and a 300-a-minute default so a route written tomorrow is covered the day it is written. Deliberately not a per-account lockout: that hands anyone who knows an employee's email the power to lock a real user out. - 2026-10-13 — [backend, shared, web] — **a brick grade is an item (ADR-051)** — the yard stops keeping two ledgers for the same bricks. Production sorted into `brick_type_id`; sales, dispatch and the closing-stock valuation all worked on `item_id`; nothing joined them. A kiln could fire 50,000 bricks and be refused a sale for want of stock, the dashboard's "bricks on hand" counted only production's half, the valuation could not see fired stock at all, and CST-01 could not say what a grade fetched because an invoice never named one. **One column closes it:** `brick_types.item_id`, unique and required, and every movement now names that item (`stock_movements.item_id` NOT NULL, the old item-XOR-grade CHECK dropped) while `brick_type_id` rides along as the grade it was. `StockService` takes either input, resolves it to the item, refuses a pair that disagrees (`STOCK_SUBJECT_MISMATCH`), and locks and sums on the item — so a sorting entry and a sale for the same pile can no longer both pass a check against the same balance. Reads that mean "bricks" now ask whether the item belongs to a grade rather than whether the row carried one, because a sale names the item alone. **What this fixes beyond the count:** CST-01's realised price and gross margin are read **per grade** (ADR-050's kiln-month fallback is superseded); closing-stock valuation can price fired bricks for the first time; the stock register's grade filter returns the sales that took those bricks out; and the current-stock report gives a grade its item's unit instead of a blank. **Migration carries existing data rather than resetting it:** each grade adopts an item of its own name where one exists and gets one created where it does not, movements are backfilled to the grade's item, and the brick-grade opening index is dropped because an opening is one per item per warehouse. The grade master now asks which item a grade is sold as, and offers only items no other grade has claimed; on edit the item is shown and not editable, because moving it would split that grade's stock history across two piles. - 2026-10-12 — [backend, shared] — P9.1a **dispatch & delivery — challan, stock OUT on confirm, delivery acknowledgement, challan PDF, and LEK-04 gate reconciliation** (DSP-01, 02, 03, 05, LEK-04). A challan is raised as a draft, confirmed when the truck actually leaves (that is when stock moves, not when the paperwork is written), and signed for on delivery; a confirmed challan cannot be cancelled, because undoing it means putting bricks back in the yard and that is a stock event with its own reason. **The decision the module rests on is ADR-041: the bricks leave the yard exactly once.** P8 had already made the invoice deduct stock (ADR-038), so a challan that also deducted would have emptied the yard twice for one load — the most expensive silent error available here, since stock drifts down with no document to point at.
